# Тест сценариуд

Энэ хавтас нь PetroNet System-ийн тест сценариуд —
[TSM](https://github.com/gerege-systems/tsm-gerege-mn)-ийн уншдаг хэлбэрээр.

Сценари яагаад энд байна вэ: тэдгээр нь энэ аппын өмч. TSM-ийн дотор гараар
бичдэг байсан бол шинэ API зам нэмсэн хүн TSM руу орж санахаас нааш сценари
хоцордог. Энд байснаар сценари кодтойгоо хамт хувилбарлагдаж, ижил PR-д
хянагдана.

## Түлхэх ба ажиллуулах

```sh
go install github.com/gerege-systems/tsm-gerege-mn@latest
ln -sf "$(go env GOPATH)/bin/tsm-gerege-mn" "$(go env GOPATH)/bin/tsm"

export TSM_URL=https://tsm.gerege.mn
export TSM_PASSWORD=...

tsm push tsm/                        # бүх сценарийг TSM руу
tsm run petronet-smoke petronet      # нэгийг ажиллуулж, дуустал хүлээнэ
```

`go install` нь бинарийг **модулийн нэрээр** — `tsm-gerege-mn` — тавьдаг.
Доорх бүх тушаал, TSM-ийн өөрийн баримт `tsm` гэж дууддаг тул холбоос хэрэгтэй;
CI мөн адил хийдэг.

`tsm run` нь сценари унавал тэг бус кодоор гардаг тул CI-д шууд тавьж болно.

## CI

`.github/workflows/ci.yml`-ийн `scenarios` ажил хоёр хэсэгтэй.

**PR бүр дээр — хэлбэрийн шалгалт, нууцгүйгээр.**
`.github/scripts/check-scenarios.py` нь энэ хавтасны YAML бүрийг задалж,
`name`/`path` бий эсэх, `auth` танигдах утга мөн эсэх, `expect.status` нь HTTP
код мөн эсэхийг шалгана. Энэ нь `tsm`-ийн серверийн шалгалтыг орлохгүй —
зөвхөн хамгийн хямд алдааг эх сурвалж дээр нь, файлын нэрээр нь нэрлэнэ.
Fork-оос ирсэн PR дээр ч ажиллана.

**main дээр — тараалт.**

1. `tsm push tsm/` — бүх сценарийг TSM руу,
2. `tsm run petronet-smoke petronet` — юу ч үүсгэдэггүй утааны сценари.

Өгөгдөл үүсгэдэг сценариудыг CI ажиллуулахгүй: тэдгээр нь продакшн дээр бичдэг
бөгөөд тэр шийдвэр хүнийх. Тэднийг гараар — `tsm run petronet-supply-chain
petronet`.

**Гурван тохиргоо хэрэгтэй.** Аль нэг нь байхгүй бол тараалтын алхмууд чимээгүй
алгасагдана — түлхэлт нь шалгалт биш:

| Нэр | Төрөл | Юу вэ |
|---|---|---|
| `TSM_URL` | repository variable | TSM хаана байна |
| `TSM_PASSWORD` | secret | TSM-ийн нууц үг |
| `TSM_GH_TOKEN` | secret | **`tsm-gerege-mn` нь ХААЛТТАЙ репо** — `go install` түүнийг татахад GitHub токен хэрэгтэй. Contents:read л хангалттай |

Гурав дахь нь өмнө нь байгаагүй бөгөөд `go install` алхам нь нөхцөлгүй
ажилладаг байсан тул PR бүр `could not read Username for 'https://github.com'`
гэж унадаг байв. «Тест сценари» улаан байх нь ердийн зүйл болж, хэн ч
хардаггүй болсон — шалгалтын хамгийн муу төлөв.

`TSM_GH_TOKEN` нь одоогоор **хүний `gh` CLI-ийн OAuth токен** (2026-09-05).
Тиймээс хоёр зүйлийг мэдэж байх хэрэгтэй: тэр нь энэ нэг репог уншихаас
хамаагүй өргөн эрхтэй, мөн эзэн нь `gh auth logout`/дахин нэвтрэх үед
хүчингүй болно — тэр өдөр CI «could not read Username» рүү буцна. Тогтвортой
шийдэл нь `gerege-systems`-ийн `tsm-gerege-mn` дээр Contents:read эрхтэй
fine-grained PAT; солиход зөвхөн энэ secret-ийг дарж бичнэ.

## Сценариуд

| Файл | Нэвтрэлт | Юу шалгах вэ | Өгөгдөл үүсгэх үү |
|---|---|---|---|
| `petronet-smoke` | үгүй | Платформ амьд, нийтийн хоёр зам, консол нийтээр нээгдэхгүй | Үгүй |
| `petronet-supply-chain` | tenant | Бааз → сав → хүлээн авалт → хуваарилалт → ШТС → борлуулалт. Хоёр талын үлдэгдэл өөрчлөгдөж байгааг тоогоор шалгана | **Тийм** |
| `petronet-border` | tenant | Импортын мэдүүлэг бүртгэж, төлвөөр урагшлуулна | **Тийм** |
| `petronet-movement` | tenant | Хоёр цэгийн хооронд хөдөлгөөн, зориудаар зөрүүтэй хаалт | **Тийм** |
| `petronet-reporting` | tenant | Тайлангийн үе, урьдчилсан бөглөлт, Excel загвар, бодлого | Үгүй |
| `petronet-oversight` | tenant | Зохицуулагчийн зургаан зам | Үгүй |
| `petronet-entitlement` | tenant | Иргэний өдрийн эрх ба ваучер | Магадгүй |

## Хоёр дүрэм

**Үүсгэсэн бүхэн буцаалттай — гэхдээ бүгд арилдаггүй.** Бичлэг үүсгэдэг алхам
бүр `undo`-тэй бөгөөд нэр нь `TSM` угтвартай. Цэвэрлэгээ нь **зөвхөн** дэвтэрт
бичигдсэнийг л устгана — «тест мэт харагдах» юмыг хайж олдоггүй, тэр хайлт
хэзээ нэгэн цагт жинхэнэ өгөгдөлтэй таарна.

Түүхтэй бичлэг үлдэнэ, зориудаар. Хүлээн авалт бүртгэгдсэн бааз, ачаа авсан
ШТС-ыг устгах зам нь 409 буцаана: тэдгээр нь тайлангийн ул мөрийн хэсэг бөгөөд
устгах нь өнгөрсөн тоог тайлбарлах боломжгүй болгоно. Хөдөлгөөн, ачилтад
устгах зам огт байхгүй — ижил шалтгаанаар.

Тиймээс `petronet-supply-chain` бүрэн ажиллахад нэг бааз, нэг ШТС үлдэнэ. Энэ нь
эвдрэл биш, аудит бүхий системийн зөв зан төлөв — **мөн `tsm-test` гэсэн тусдаа
байгууллага байгаагийн шалтгаан.** Хуримтлагдвал бүхэлд нь дахин эхлүүлнэ:

```sql
delete from registry.tenants where slug = 'tsm-test';  -- cascade бүхнийг авна
```

Дараа нь байгууллага, роботын дансыг дахин үүсгэнэ.

**Шалгалт нь өөрийн үүсгэсэн зүйл дээр байх ёстой.** Жагсаалтын зам —
`GET /depots` — өмнөх бүх ажиллуулалтын үлдэгдлийг тоолно. Түүхтэй бааз
устгагддаггүй тул `count` удаа бүр өснө: тийм шалгалт цэвэр байгууллага дээр
НЭГ л удаа өнгөрнө. Дахин ажиллуулах боломжгүй багц бол багц биш. Тиймээс
сценари бүр өөрийн `${depot_id}`, `${station_id}` замаар шалгана.

**Бодлогын хариу бол алдаа биш.** `petronet-entitlement` дээр ваучер үүсгэх
алхам 201-ийг ч, 409-ийг ч зөв гэж үзнэ: тухайн өдөр эрх байхгүй байх нь
системийн зөв ажиллагаа. Роботыг бодлогын шийдвэрийг «унасан» гэж дуудуулах нь
дараа нь хэн ч уншихаа больдог улаан гэрэл үйлдвэрлэнэ.
