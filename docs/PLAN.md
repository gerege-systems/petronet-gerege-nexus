## 1. Хаана байна вэ — 2026.08.31-ний хэмжилт

`modules/petro`: **3,326 мөр** Go (тестээс бусад), **7 миграц**, **11 хүснэгт**.
`frontend`: **73 хуудас**. Платформын цөм нь dependency, энэ репод цөмийн код
байхгүй.

Барьсан зүйл нь нийлүүлэлтийн гинжний загвар:

```
гааль (petro_customs_shipments) → бааз (petro_depots, petro_depot_tanks,
  petro_depot_receipts) → тээвэр (petro_dispatch_trips) → ШТС (petro_stations,
  petro_station_inventory, petro_station_receipts) → иргэн (petro_entitlements,
  petro_vouchers) · нэмэлт: petro_batches, routes
```

Хоёр зарчим нь аль хэдийн кодод суусан бөгөөд энэ нь дэлхийн жишигтэй санамсаргүй
таарсан хоёр газар:

- **Литрийн талбар байхгүй.** Түвшин нь хүлээн авалтуудын нийлбэр; түүнийг
  дарж бичих талбар нь доорх бүх баримтыг зөвлөмж болгоно (`depots/page.tsx`)
- **Мэдүүлсэн ба хэмжсэн хоёр тоо тусад нь.** Хүлээн авалт нь ачааны бичгийн
  тоо ба хэмжигчийн тоо хоёрыг зэрэг хадгална — зөрүү нь өөрөө өгөгдөл
  (`receipt.go`, `depot.go`)

### Гинжний зургаан үе — хянахаас гадна удирдах

Систем нь ажиглалтын самбар биш. Үе шат бүрт **харах** ба **үйлдэл хийх** хоёр
багана байна; зөвхөн эхнийх нь байвал энэ нь тайлангийн сан, систем биш.

| Үе шат | Хянах | Удирдах (үйлдэл) | 1-р сар |
| --- | --- | --- | --- |
| **Импорт** | Гэрээ, захиалга, тонн, үнэ, ирэх хугацаа | Импортын төлөвлөгөө батлах, хуваарилалт | Загвар бий; **гар бүртгэл + тайлан** |
| **Хил** | Гаалийн мэдүүлэг, партийн дугаар, чанарын үзүүлэлт | Мэдүүлгийг баталгаажуулах, зөрүү тэмдэглэх | Гар бүртгэл; гаалийн интеграц 2-р сард |
| **Терминал** | Савны түвшин, чөлөөт багтаамж, улсын нөөц | Хүлээн авалт бүртгэх, савны статус, түдгэлзүүлэх | **Бий** (`depot_receipts`) + шалгалт |
| **Тээвэр** | Автоцистерн, замнал, ETA, зөрсөн зогсолт | Хөдөлгөөн нээх, хаах, зөрүүтэй гэж тэмдэглэх | **`petro_movements` — 2-р д/х** |
| **ШТС** | Үлдэгдэл, үнэ, хошуу, дараалал | Хүлээн авалт, үнэ, статус, тусгай зөвшөөрөл | **Бий** (`station_receipts`, `grades`) |
| **Түгээлт** | Борлуулалт, иргэний эрх, ваучер | Эрх олгох, ваучер, хязгаар тогтоох | **Бий** (`entitlements`, `vouchers`) |

Зохицуулагчийн талын удирдах үйлдлүүд нь энэ сард нэмэгдэнэ: тайлан **батлах,
буцаах**, объект **түдгэлзүүлэх**, хөдөлгөөнийг **хаах, зөрүүтэй гэж
тэмдэглэх**, эрсдэлийн жагсаалтаас **даалгавар үүсгэх** — бүгд аудитын мөртэй.

### Хоёр баримт, нэг систем — хамрах хүрээ ба нарийвчлал

«PetroNet-ийн бүрэн төлөвлөгөө» (`docs/petronet-plan.md`, дотоод) нь өөр эхлэлийг санал болгодог:
**POS → өгөгдөл → харагдац → ваучер → хяналт**. Тэр нь буруу биш — эцсийн үнэн нь
түгээгүүрийн тоолуур дээр байдаг. Гэхдээ хоёр зам нь өөр зүйлийг эрт өгдөг:

| | **Хамрах хүрээний зам** (энэ сар) | **Нарийвчлалын зам** (2–4-р сар) |
| --- | --- | --- |
| Эх үүсвэр | ААН-ийн тайлан, Excel, веб форм | POS, хошуу, ATG |
| Хэдэн объект | 1500 ШТС — долоо хоногт | 20–30 ШТС — сард |
| Нарийвчлал | Өдөрт нэг мөр, ±1–2% | Гүйлгээ тутам, ±0.3% |
| Юуг өгдөг | «Хаана хэдэн литр байна» — улсын зураг | «Хаана алдагдаж байна» — гүйлгээний үнэн |
| Өртөг | Код ба дагалдан ажиллах хүн | ШТС тутамд $700–1,200 тоног төхөөрөмж |

Дараалал нь: **хамрах хүрээ эхэлнэ, нарийвчлал дагана.** Грек ч гэсэн хошууны
системд хоёр жилийн шаталсан хугацаа тавьсан. Нэг сард 1500 ШТС-д төхөөрөмж
суулгах боломжгүй; нэг сард 1500 ШТС-ыг тайлагнуулах боломжтой.

Гэхдээ хоёр зам нь **нэг өгөгдлийн загвар дээр** нийлэх ёстой: тайлангийн мөр
болон ATG-ийн заалт хоёр ижил талбар (түвшин, температур, нягт, 15 °C литр)
бөглөнө; ялгаа нь зөвхөн `source` багана. Ингэвэл 2-р сард мэдрэгч ирэхэд
шилжүүлэх миграц биш, шинэ мөр л нэмэгдэнэ.

### Модулийн бүтэц — нэг модуль хэвээр

Бүрэн төлөвлөгөө 14 модуль санал болгосон (`pos`, `pump`, `tank`, `voucher`,
`allocation`, `oversight` …). Энэ сард **салгахгүй**: бүгд `modules/petro`
дотор, нэг миграцын түүхтэй. Салгах шалтгаан нь одоо байхгүй — нэг баг, нэг
байрлуулалт, нэг эрхийн загвар. Салгах цаг нь ирмэгийн агент (`edge/`) гарч,
өөрийн хувилбарын мөчлөгтэй болох үе.

**Нэг өгүүлбэрээр:** нийлүүлэлтийн гинж баригдсан, **зохицуулалтын гогцоо
дутуу** — ААН өөрөө тайлагнаж, төр шалгаж, буцааж, батлах урсгал.

## 3. 30 хоногийн зорилго ба хүлээн авах шалгуур

**Гинж:** ААН тайлангаа өгнө → систем шалгана → төрийн ажилтан батална →
шийдвэр гаргагч бодит зургийг харна → тайлагнаагүй нь нэрээрээ гарна.

Энэ гинж бүтэн ажиллавал систем **амьд**. IoT, гааль, мобайл, BI бүгд үүн дээр
нэмэгдэнэ — доор нь биш.

### Хүлээн авах шалгуур (09.30-ны байдлаар)

| # | Шалгуур | Зорилт |
| --- | --- | --- |
| 1 | Порталд нэвтэрч, өөрийн объектоо баталгаажуулсан ААН | **≥ 20** (сарын эцэст ≥ 50 урилгатай) |
| 2 | Эзэмшигчтэй холбогдсон ШТС/бааз | **≥ 300** объект |
| 3 | Тайлангийн хамрах хүрээ (тайлагнасан ÷ бүртгэлтэй) | **≥ 80%**, сүүлийн 2 долоо хоногт |
| 4 | Хугацаандаа ирсэн тайлан (timeliness) | **≥ 80%** |
| 5 | Автомат шалгалтаар илэрсэн зөрчил засагдах дундаж хугацаа | **< 24 цаг** |
| 6 | Дашбоардын хариу (p95) | **≤ 3 с** |
| 7 | API-ийн хариу (p95, 1000 зэрэг хэрэглэгч) | **≤ 1 с** |

### Нөхцөлдүүлэлт — таван тэнцэл

Загварын жинхэнэ зорилго нь тайлан хадгалах биш, **зөрүүг тоо болгох**. Бүгд
15 °C-т шилжүүлсэн литрээр:

```
Гаальд мэдүүлсэн   − Терминалд хүлээн авсан                    = ΔA  хилийн алдагдал
Терминалаас ачсан  − ШТС-д хүлээн авсан                        = ΔB  тээврийн алдагдал
ШТС-д хүлээн авсан − Түгээсэн − Савны үлдэгдлийн өөрчлөлт      = ΔC  ШТС-ын алдагдал
Түгээсэн           − e-Barimt-аар бүртгэгдсэн                  = ΔD  татварын зөрүү
Ваучераар олгосон  − Түгээсэн                                  = ΔE  ваучерийн зөрчил
```

Хүлцэл: ΔA ≤ 0.3% · ΔB ≤ 0.3% · ΔC ≤ 0.5% · ΔD ≈ 0 · ΔE ≤ 0.2%. Хэтэрвэл
автомат кейс үүсч, зохицуулагчийн дараалалд орно.

| Тэнцэл | Эх өгөгдөл | Есдүгээр сард |
| --- | --- | --- |
| **ΔA** | Гаалийн мэдүүлэг ↔ терминалын хүлээн авалт | **Хэсэгчлэн** — мэдүүлэг гараар орно, автомат нь 2-р сард |
| **ΔB** | Хөдөлгөөний мэдүүлсэн ↔ хүлээн авсан литр | **Бий** — `petro_movements` дээр өдөр бүр |
| **ΔC** | ШТС-ын нээлт + хүлээн авалт − борлуулалт = хаалт | **Бий** — тайлангийн шалгалтын гол дүрэм |
| **ΔD** | Түгээсэн ↔ e-Barimt | 3-р сар — POS/e-Barimt интеграцтай хамт |
| **ΔE** | Ваучер ↔ түгээсэн | 3-р сар — ваучер идэвхжсэний дараа |

ΔB ба ΔC хоёр нь **гар тайлангаас гарна** — тиймээс энэ сард. Тэдгээр нь
«хаана алдагдаж байгаа нь мэдэгддэггүй» гэдэг асуудлыг эхний удаа тоо болгоно.
